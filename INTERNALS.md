# nexttuesday.art: how the site is built

How the site is put together, for whoever changes it. The visitor-facing
facts (what NTS is, the copy) live in the memex corpus; this file is about
the code.

One site, five pages: the home (`/`), the three worlds (`/embers/`,
`/not-not-philo/`, `/intersect/`) and `/events/`. Every page is static
HTML at its own URL under `site/`; all the CSS and JS they share is in
`site/_nts/`. The type is Fraunces and Instrument Sans by default, IM Fell
inside INTERSECT only; one favicon; a nav that keeps its font on every
page. The home is an orrery; scrolling opens each section as a disc from a
ring on its top edge (the apertures), inside the worlds too; a world page
reached from the home lets its colours bleed in from its entity.

## Layout of the repo

```
site/              what GitHub Pages serves (the `site` branch, see Publishing)
  index.html       the home: the orrery, the windows into the worlds, the ledger
  embers/  not-not-philo/  intersect/  events/      the four other pages
  404.html         the not-found page (standalone, no shared layer)
  CNAME, .nojekyll the domain; .nojekyll lets Pages serve _nts/
  _nts/            everything the pages share
    nts.css        tokens, ground, type, sigils, header, footer, sections,
                   lift, ledger, draw-in, the bleed-in
    pages.css      the pages' own layout: the home's turn and sections, the
                   world heroes and sections, the events page
    orrery.css     the home's orrery, the world windows, the
                   orbit trace on the world pages, falling into a world
    apertures.css  sections opening as discs from their rings; last, so
                   it takes over the handovers
    nts-head.js    runs in <head>: html.js, the bleed's before/world state,
                   the world list and the orb's name on arrival
    nts.js         header state, draw-in, the bleed-in
    orrery.js      the emblem's stop, and naming the body you fall into
    sigils.svg     the sigil sprite (generated by tools/gen-sigils.mjs)
    parts/         emblem-core.html, emblem-orbits.html and the still frames (inlined by sync)
    content/       site.json, events.json, copy.json: the one content source;
                   site.json's `initiatives` is the registry of the pages
                   (see Adding an initiative)
    worlds/        one kit per initiative
      embers.css   embers.js (the hearth; also the fragment)
      philo.css    cubes.js (the figure) + philo.js (the entity; also the fragment)
      intersect.css ascii.js (the ASCII solid; also the fragment)
  <old>/…          redirect stubs for URLs of earlier drafts (see Redirects)
tools/
  sync.mjs         fills the shared regions of every page from _nts/content
  gen-sigils.mjs   writes _nts/sigils.svg
  gen-emblem.mjs   writes _nts/parts/emblem-*.html (the home emblem)
  gen-stills.mjs   writes _nts/parts/still-*.{svg,txt}
```

## Changing a page

Edit the page's HTML or the stylesheet that owns the rule (above), run
`node tools/sync.mjs` after every edit to a page, and
`node tools/sync.mjs --check` before you commit (exit 1 means a page is
out of date). Copy changes go in `_nts/content/copy.json`, not the HTML
(see The content source and sync).

The stylesheets load in one order on every page: `nts.css`, the page's
world kits, `pages.css`, `orrery.css`, `apertures.css`. Later files build
on earlier ones: `apertures.css` turns the home's world windows and its
`.handover`s, and the bands inside the worlds, into apertures, and switches
off the bloom `orrery.css` would otherwise give the windows.

Hard rules for every page: static HTML that reads with JS off; Google
Fonts only, one `<link>` per page with only the families that page uses;
no Solstice, farm, WhatsApp, payment links or personal names; no RAVEMBER
2026 date or venue; English; copy only from `_nts/content/copy.json`;
`<title>`, description, og:title, og:description, theme-color, the one
favicon (the NTS sigil in ink on the beige, the same `<link rel="icon">`
on the home, the worlds and events; 404 has its own); no horizontal scroll at 320/360/390; 16px minimum gutter; AA
contrast, settled and in every transition (the bleed-in's crossing keeps
each glyph in the colours of the ground under it); functional text 11px
or more; canvases cap DPR (at 2; INTERSECT's ASCII at 3, for its glyphs), pause off-screen and in hidden tabs, and
draw one still under prefers-reduced-motion. What the design keeps: the
orrery (sun, beads on their orbits, the events star), the windows into
each world as you scroll, falling into a satellite, the
EMBERS tetrahedron at its size and its section rhythm, NOT NOT PHILO's
rings and triangle.

The one exception to AA contrast: the EMBERS hero label band, cream on
`--embers-fire` at 3.87:1. It stays in the brand's fire red, the same red as
the bar beside it, rather than a darker one that would pass.

## Page skeleton

```html
<html lang="en">
<head>
  … meta, title, the one favicon, the page's Google Fonts link …
  <link rel="stylesheet" href="/_nts/nts.css">
  <link rel="stylesheet" href="/_nts/worlds/<world>.css">   <!-- the page's world, or all three on home -->
  <link rel="stylesheet" href="/_nts/pages.css">
  <link rel="stylesheet" href="/_nts/orrery.css">
  <link rel="stylesheet" href="/_nts/apertures.css">
  <script src="/_nts/nts-head.js" data-bleed="scroll"></script>   <!-- sync writes data-bleed on the pages marked bleed -->
  <script src="/_nts/nts.js" defer></script>
  … world scripts, deferred …
</head>
<body data-world="embers">          <!-- nts | embers | philo | intersect -->
<!-- nts:sprite --><!-- /nts:sprite -->
<!-- nts:header --><!-- /nts:header -->
<main>…</main>
<!-- nts:footer --><!-- /nts:footer -->
</body>
```

`data-world` on `<body>` picks the world's tokens. It also works on any
element: a `<section data-world="embers">` on the home page is in EMBERS'
world (ground, text, accent, selection), which is how the windows into the
worlds are built. Do not put `data-world` on things that are merely about
a world; the ledger rows use `data-of` for that reason.

## Components

Sigils. Six symbols in the inline sprite: `#sigil-nts` (ring, heptagram,
point), `#sigil-embers` (fire triangle, three waves), `#sigil-philo` (the
impossible triangle), `#sigil-intersect` (crossroads in a broken ring),
`#sigil-star` (the ✴︎, for events and links), `#sigil-gathering`
(Tuesdays). Use:
`<svg class="nts-sigil sigil-embers" aria-hidden="true" focusable="false"><use href="#sigil-embers"/></svg>`.
`.sigil-<world>` sets the colour; `.lg` and `.xl` the size; inside `.go`
and `.nts-nav a` they size themselves. Every stroke has `pathLength="1"`,
which is what lets draw-in work with one dash rule.

Header and footer come from sync (`<!-- nts:header -->`, `<!-- nts:footer -->`).
The header is sticky, one row, 52px; on phones the wordmark hides and the
four destinations stay in one tap, spread from the sigil to the gutter
(the `nav` takes the free width), as far from the sigil as from each
other. It takes `--w-bar-bg`/`--w-bar-fg`, so
its colours follow the world; its type never does: the nav is Instrument
Sans 600 at .72rem (.7rem under 640px, .6875rem under 360px) on every page,
and `intersect.css` leaves it alone. The current page is marked by its
sigil before the label and a 2px bar in `--w-accent` right under the
label, 4px below the baseline (`.nts-nav a span::after`): the marker
belongs to the word, not to the bar's bottom edge, where it would float. Hover and focus show the same bar faintly in the text
colour. Do not add a menu button or hide the header.

Sections: `.sect` (vertical rhythm), `.sect-head` (sigil + h2), `.rule`
(and `.rule.draw` to grow in), `.band` (a field in `--band-bg` and
`--band-fg`, which each band sets), `.go` (a link that leads somewhere, with the
star), `details.reveal` (a whisper on tap).

The lift: add `.lift` to any block link or card. Hover and focus lift it 4px
on `--ease-lift`, with a soft offset shadow; active presses it.

The ledger: `<!-- nts:events -->…<!-- /nts:events -->` renders every
event, upcoming then past, newest past first. Options on the open marker:
`upcoming` or `past` (one group), `world=embers` (one world), `limit=3`,
`heading=h2|h3|none`. Each row is `li[data-of="<world>"]` with the world's
sigil, a mono date, a Fraunces title (linked when the event has a page), a
`.kind` chip in the world's colour (on the home: a bone label with the
initiative's code dot), the place and the line. Rows have ids
`ev-<id>` from events.json.

The emblem: the home's sun, inside `.orrery`. Its drawing is static,
generated by `tools/gen-emblem.mjs` into `_nts/parts/emblem-core.html`
and `emblem-orbits.html` and inlined by sync:
```html
<div class="orrery">
  <!-- nts:emblem core --><!-- /nts:emblem -->     the star, ring, dial, bands, sunburst, marks, pyramids, the eye (.e-stop), beams
  <div class="pivot orbit o-embers"><a class="bead" …>…</a></div>   …the four beads, by hand
  <!-- nts:emblem orbits --><!-- /nts:emblem -->   the four orbits with their star dots (.st, decorative: aria-hidden)
</div>
<div class="turn"><p class="secret incant">…</p></div>
```
Edit the generator, run it, then `node tools/sync.mjs`; never edit the
parts by hand. Every layer is a whole SVG or box that the compositor
turns (a transform on an SVG child repaints the drawing every frame):
the orbits (`.e-o66` … `.e-o96`, each with its dots, `.e-pv`) and the
ring and bands turn on `turn`, neighbours in opposite directions; the
beads ride their orbits (`--r`, `--a`, `--p`, `--d` in `orrery.css`, from
each initiative's `orbit`). The dial ticks
counter-clockwise in 60 eased steps a minute: `.e-tick` runs two animations, `e-minute` on `rotate`
(steps of -6deg) and `e-tick` on `transform` (each second's eased last
.24 s); their sum is the tick, so set both to the same `currentTime`.
Inks that change with the ground are `currentColor` on a `k-*` class, set
from `--e-*` on `.threshold`; SVG attributes cannot read `var()`, so fixed
inks are token `style` attributes.

The eye (`.e-stop`, `aria-pressed`) stops the machine (`orrery.js`):
each part's angle is read once, its animation dropped (`.orrery.is-still`)
and pinned inline, then `.is-gliding` eases it in 1.6 s to the stop pose
(beads and dots at the hours of a clock, layers at 0); `.is-stopped` on
`.threshold` fades the dial and its marks (the north stays), hands the
pyramid and beam over to their ink copies, flips the pyramid,
draws the star at the back and shows `.turn .secret`. Again, each part's
animation restarts at the time matching where it stands. Under reduced
motion nothing turns or draws, the fades keep their 1.6 s (they beat the
global .01ms rule), and the pyramid hands over to an upside-down copy.
The ground: the emblem sits on the page's beige, no plate, grid or picker;
the `--e-*` on `.threshold` are the Black sun's inks. Each bead rides in a
moat of the page's ground, which is the face's own shadow (`.bead-face`, below).
The click hint is the bead's `::after`: a thin ring in `--e-halo` that
grows off the bead and fades, the eye's beam in small, on every pointer
type; one bead at a time (18 s cycle, staggered 4.5 s, set clear of the
eye's touch beam). It rides the bead, outside the `.face` that the fall
names `orb`, so the morph never captures it; no ring under reduced
motion (S5, S6).

## The bead (`.bead-face[data-of]`)

Every round body that wears a world is one element, `.bead-face` with
`data-of="embers|philo|intersect"` and the sigil `<svg class="nts-sigil">`
inside; `orrery.css` is its one definition. Face (`--of-base`) and sigil come
from the world's fixed tokens, never from `--w-*`, which the bleed swaps
(which token is which comes from the initiative's `colours.face`, through sync). The
face draws its own edge, a ring in the sigil's colour as a radial gradient
(not a second inset shadow: that leaves a fringe outside the face); the moat
is a box-shadow spread of `--ground`, set on `main` and, for a
ring on a seam, to `--ecl-out`. Each place sets only the size; the sigil is 58%
of the face. Places: the home emblem's beads, the home windows' rings, the
events' small orrery and the rings of the bands.

- **Rings on a seam.** A ring on a seam is the band it opens: its face is
  `--ecl-bg`, its sigil and seal the world's (nts/events: `--ecl-fg`,
  `--code-events`). The EMBERS summon ring is the exception: its band is the
  sigil's own colour, so it keeps its world's plain face, red sigil on black.
- **Seal lights.** Hover and focus add no ring at the edge: `::after` is the
  seal drawn full sigil colour and twice as thick, faded in by opacity, with
  the lift's shadow. Keyboard focus is a 2px ink outline, 5px clear of the moat.
- **NTS rings.** `data-of="nts"` and `"events"` (the home's `#words` and
  `#yet-to-come`, the /events/ ledger) follow the same rule: sigil and seal
  `--ecl-fg` (events: `--code-events`).

The Events star and the /events/ sun are not beads. O1, O8, O11, O12 and O13 hold
all of this.

## The home (`orrery.css`, `orrery.js`) and the apertures (`apertures.css`)

The orrery: the emblem is the sun, the sigils of the
three worlds and the events star ride its orbits
(`.pivot` is a static zero-size point; its child carries one animated transform, `orbit`, which turns around the point and counter-rotates so the `.bead` stays upright).
No key names the bodies: the name follows the emblem, and a quiet pulse
(below, paused while the machine is stopped) is the only hint that a bead opens. On a phone the emblem is sized
so its outer orbit is the world pages' trace ring: the same diameter and centre
on screen, on every phone viewport, portrait or landscape (the ring's caps
`--ring-cap` and `--entity-w`, and `--ring-inset`, `--hero-top` and
`--orbit-share`, are in `orrery.css`). `.sky` runs to the screen's edges
and does the clipping, so a body riding past the emblem's box (the events
star at three o'clock) is never cut by the box; S1 in
`tests/behaviour/sky.spec.mjs` holds the match. One known exception: EMBERS'
`max-height: 70svh` (`embers.css`) makes its entity shorter in short landscape,
so its ring sits higher than the other worlds'. Scrolling travels to each world: `section.world`
with `data-world`, its orb (`.orb`, holding the
world's live fragment) and its words. The orb is a portal, not a card: hover, keyboard
focus and a press open it into the disc and never lift it or cast a shadow
off it (`orrery.css`, "the orb"). The orb's box is the window, as wide as
it always was (O5), and at rest the figure in it is untouched: no transform
and no clip but the disc's own round edge (O6), so a live figure costs no
more to composite than on a plain disc (P6 checks the idle orbs paint
nothing but their canvases). Around it lie a ring of bare ground (`--lid`)
and the orbit's gap (`--orbit-gap`), both in cqi of the window, so the
limb (`.orb::after`) can grow from the window's edge exactly to the orbit
as it fades. The opening moves and fades layers painted once (transform and
opacity only), the same parts on every world, and nothing is drawn over the
figure but the limb; O3 and O4 in `tests/behaviour/orbs.spec.mjs` hold that. Between the sections sits a
`.handover`, the gap where the next aperture's ring sits. The
header's `.is-scrolled` comes from an 8px sentinel at the top of the page,
watched by an IntersectionObserver (a passive scroll listener where there is
none). Falling into a world is a cross-document view transition from
the body you tapped (`orrery.js` names it `orb`), into the world page's
`.hero .entity`, which carries the trace of the orbit.
A world hero is a stacking context, layered so the figure paints over the trace: the trace is at z-index -2, EMBERS' hearth canvas at -1, PHILO's ring plate at -4 and its fade at -3.
Leaving, each side names its `orb` at `pageswap` (`orrery.js` on the home,
`nts.js` on a world page). Arriving, the new side is named at `pagereveal`,
the frame its snapshot is taken, which comes before the deferred scripts
and can come before the page is parsed: so `nts-head.js` names it (the
hero entity, or the home's body via `NTS.body`), and each of these pages
has `<link rel="expect" href="#…" blocking="render">` on an id after
everything that may be named (`#title` on the worlds, `#ledger` on events,
`#h-field` on the home; T6 in `tests/transitions/morph.spec.mjs` checks
the order). `NTS.world(url)` in `nts-head.js` answers from `PATHS`, and
`NTS.body` from `BODY`, both generated from the registry.

The apertures. A section that changes ground is an aperture: `.ecl`,
inset in the page so the ground around it stays in view, with the
section's sigil in a ring on its top edge (`.ecl-ring`) and its content in
`.ecl-win > .ecl-disc > .ecl-in` (the card, the disc, the card's ground
and content). As it scrolls into view, its ground opens as a disc from the
ring, with a thin bright limb on the disc's edge, scroll-driven on the
aperture's view timeline where `animation-timeline: view()` exists and
`html.js` is set; open everywhere else and under reduced motion. The
compositor runs it: each part animates `scale`, `rotate` or `opacity` on
its own, nothing animates a custom property or a mask. `.ecl-disc` is
scaled from the ring point under a fixed circular clip of radius `--ecl-r`
(the card's farthest corner, set by a ResizeObserver in `nts.js`),
`.ecl-in` by the inverse, so the edge passes over a still card; the limb
is a disc of its colour behind the ground, scaled a step ahead of it. The
disc rests at scale .001, never 0, so a figure measuring itself with
`getBoundingClientRect` reads its real size while closed. It follows the scroll both
ways only until the disc is complete: then it latches. `nts.js` watches
each `.ecl` with an IntersectionObserver whose root is cut at the
bottom by `--ecl-open-end` (`apertures.css`, in vh, also the end of
`animation-range`, which starts at `--ecl-open-start`: 25vh / 70vh at every width,
so the disc opens while the ring climbs from 75% to 30% down the screen), and adds `.is-open` (every part's animation off), so
scrolling back up never closes it again, for the rest of the page load
(every part's animation stops, so each rests open). On the home the apertures are the world windows
(`.world.ecl`) and the two NTS bands; inside a world they are its bands.
Colours come from `--ecl-bg`, `--ecl-fg`, `--ecl-out` and `--ecl-limb`
(the file head has the markup). A band's words fade in only once the disc
has passed them (`--ecl-hold`, `--ecl-show`), so no line is shown cut by
the edge. The world pages' bleed-in uses the same figure: a disc opening
from the page's entity.

## Behaviours

Draw-in. Put `data-nts-draw` on a container (its sigils and any `.drawn`
strokes draw themselves when it enters view) or on a `.nts-sigil` itself;
`data-nts-draw="fade"` fades and lifts the element instead; `.rule.draw`
grows from the left. Siblings in one parent stagger by 140ms through
`--draw-delay`. Everything is gated on `html.js`, so with scripts off (or
reduced motion) nothing is held back.

The world bleed-in. A world page loaded with
`<script src="/_nts/nts-head.js" data-bleed="scroll">` starts in the NTS
colours when the visitor arrived from the home page, and its world's
colours bleed in once, driven by the scroll. Landing directly, reloading,
or asking for reduced motion gives the world from the first frame.
EMBERS' bleed-in is its night-fall: paper to night. The three worlds
behave the same.

- Detection, in `nts-head.js`, before paint: `nts.js` sets
  `sessionStorage["nts:from"] = "home"` when a link to a world page is
  clicked (`NTS.world`, the registry's pages; the events page is one of
  them but runs no bleed) on any page except a world page whose bleed has
  settled (`html[data-bleed-state="world"]`; only pages running the bleed
  carry the attribute). So the next world opens beige from the home, the
  events page or any ordinary page, and from a world page still `before`
  or `in`, but not from a settled one. Except that a link inside a block
  already in the destination's colours (its closest `[data-world]` equals
  `NTS.key(world)`, as the home's world panels `a.orb` and `a.go`) sets the
  flag to `"direct"`: the world opens as `world`, and the referrer fallback
  is skipped. The dial beads, nav, events list and footer stay beige.
  `nts-head.js` consumes the flag;
  failing that it accepts a same-origin referrer that is not a world page.
  It then sets `html[data-bleed="scroll"][data-bleed-state="before"|"world"]`.
  Sync writes `data-bleed="scroll"` on the page of each initiative
  marked `bleed`, and the paths of `NTS.world` from the same list; R3 in
  `tests/static/registry.spec.mjs` and T3 in `bleed.spec.mjs` hold them
  together.
- The before state is CSS: `html[data-bleed-state="before"] [data-world]`
  reads the NTS `--w-*` tokens (section 11 of `nts.css`), and each kit
  undoes what else its world brings (`--embers-glow`, `--hearth-base`, the
  penrose ink and ground (its red stays the title's), `--grain`). The same
  rules apply to `.nts-bleed-old` while the state is `in` (not the grain,
  below). The root itself
  (`html`) reads the NTS set while the state is `before` or `in`: its ground
  is what the arrival's view transition lies on, and a world's dark
  there would show through any see-through moment on the whole page but the
  header. The root pair has none: the old snapshot stays opaque (no
  animation) and the new one fades in over it (`vt-in`, 420ms), because
  Safari paints a dark backdrop behind a fading pair (`T7` in
  `tests/transitions/solid-root.spec.mjs`). The
  kits set the root's world tokens at `:root`'s weight
  (`:root:where(:has(> body[data-world=…]))`), so the arrival selectors win;
  a settled world page has its own ground on the root. Only three states exist: `before`, `in` (from
  `DOMContentLoaded` until the disc is complete) and `world`.
- The crossing, in `nts.js`, only ever crosses the hero, and the
  compositor does it: during the scroll the main thread reads no layout
  and writes no styles beyond a class on the header. At `DOMContentLoaded`
  (after every deferred script, so the figures are mounted) it clones the
  hero as it is into `.nts-night`, a body-level layer in document px from
  the top of the page to the hero's foot, over the hero and under the
  header, on the world's ground (`data-world` on `.nts-night-in`). The
  copy is shown through a disc: `.nts-night-disc`, a circle centred on
  the entity whose radius reaches every corner of what is in view of the
  hero once it is complete, scaled from 0 to 1, with the copy inside it
  (`.nts-night-in`) scaled by the inverse around the same centre so it
  stays in place. Both are Web Animations on a `ScrollTimeline` over the
  root, from the top to the scroll where the hero is half gone or, if sooner,
  a little before the world's name (the hero's h1) would reach the foot
  of the sticky header (at least a tenth of the viewport), smoothstepped through the keyframes, which
  are dense enough (every 4% of scale) that the two linear
  interpolations stay each other's inverse to well under a pixel. The
  page's tokens flip to the world's at the same moment, except on the
  hero itself and the header, which keep `.nts-bleed-old`; so everything
  below the hero is in the world from the start and is never crossed, and
  the hero keeps its NTS ground (`main .hero` gets a full-bleed beige
  ground, `box-shadow` clipped at its foot, while the state is `before`
  or `in`). The parts outside the hero drop `.nts-bleed-old` when the
  disc covers them whole, their farthest corner (a scroll position worked
  out with the geometry; a sticky header moves down with the scroll), and
  crossfade (`--dur-bleed-fade`, 200ms). Crossed at its centre, the
  full-width header went dark over the NTS ground still around the disc,
  its backdrop blur smearing the disc's edge across it. Only the part itself
  fades; everything inside it has no transition and inherits the fading
  colour, so ground and ink move in one step (a transition on each level
  restarts whenever its parent's value moves, and the labels trailed their
  ground by a fade per level: dark ink on the dark bar for about a second
  on iPhone). Marks with a colour of their own (the accent sigil, the
  current page's bar) change at once. `T8` in
  `tests/transitions/header-bleed.spec.mjs`. A texture that is
  part of the world's ground is not one of those parts: INTERSECT's grain
  (`.intersect-grain`, a body-level layer under the content) is on from the
  start of `in` (it is off only in `before`). While the state is `in` it
  lies over the copy (`z-index: 3`, above `.nts-night`, under the header),
  so the disc and the page below it carry one grain at one raster scale (a
  copy of it inside the scaled layer would be resampled and read as another
  texture), and they are the same dark as the settled page. The copy's
  layer runs 2px past the hero's foot, so its scaled bottom edge never lands
  in the hero's last row and lets the paper show as a line. CSS animations in
  the copy are set in step with the original's; draw-ins in it are
  shown. When the scroll reaches the end the world settles for good: the
  copy goes, the classes go, the state is `world`. Scrolling back up before
  that closes the disc. A resize of the hero (or the window) measures
  again and rebuilds the keyframes.
- Where `ScrollTimeline` is missing (Firefox, Safari before 26) the same
  animations are paused and a passive scroll listener sets their
  `currentTime` once a frame: still transforms only, no layout reads, a
  frame behind the scroll at most.
- Hooks, on `window.NTS.bleed`:
  - `twin(el)`: the copy of a hero element while the copy exists, else
    `null`. A live figure draws its night into its twin and its day into
    itself: the hearth, the triangle and the ASCII solid draw on their twin
    canvas. Each side is drawn only
    while some of it shows (`progress()` above 0 for the night, below 1 for
    the day), at the figure's own frame rate; nothing is redrawn because
    the page scrolled.
  - `progress()`: the disc's progress, 0..1, worked out from `scrollY`.
  - The event `nts:bleed` on `window`, with `detail { phase: "start" |
    "end", world }`: when the copy is made (twins exist from here) and
    when it goes (each figure redraws itself at once in the world's
    colours, so the swap is not seen).
- Caveats: a hero element that is fixed, or sized from the viewport in a
  way its copy cannot follow, would not line up with its copy. The copy is
  a snapshot of the hero's DOM at `DOMContentLoaded`: what a script changes
  in the hero later shows only in the original, unless it writes to the
  twin too (as the figures do). Nothing in the copy carries a
  `view-transition-name` (`.nts-night *` sets `none`), so the entity
  named `orb` on arrival from home stays the only one. The EMBERS bar sits over the copy
  (`z-index: 3`): its colours are the same by day and by night. Text
  stays crisp in the copy in Chromium; a browser that rasterises the
  counter-scaled layer at a low scale could blur it while the disc opens.

### World hero text

The hero's three lines (the name, the label, the punchline) are in
`.hero-text`, in `pages.css`; each world's lines differ in colour and face,

points here.

  container's width divided by the text's width in em, so the line just fills
  the column at any width and never wraps (`white-space: nowrap`). Each

  the face as they are: measure it again when either changes.

  column. The punchline would widen it, so it is `width: 0; min-width: 100%`:
  as wide as the track, not wider, and its text may run past it.

  `--w-bg` on `--w-fg` (reverse video); NOT NOT PHILO: white on

  z-index -1, which relies on `.philo-hero .hero-text` being a stacking
  context).

  `.label-short` (`<world>.eyebrow.short`, "<X> series · NTS" with an

  threshold from the page's root font size.
- INTERSECT: the label and the punchline start under the I, not the prompt:
  `margin-left: calc(.815 * var(--title))`, the prompt's width plus its space
  in em of the title (measured as the `--fit` factors are).
- NOT NOT PHILO's punchline is in the display cut of Fraunces
  (`"opsz" 144, "SOFT" 100, "WONK" 1`).

Data attributes tune it (see the file head). Drag turns, tap stokes,

copy and the day into itself, both from one geometry. On `/embers/` the canvas is the

NOT NOT PHILO (`worlds/philo.css`, `worlds/cubes.js`, `worlds/philo.js`);

Classes: `.philo-bar` (the red label with the misregistered charcoal plate;
`.sm`, `.caps`), `.philo-key` (the red extra-bold key word),
`.philo-rings` (the hero's full-bleed plate of engraved rings, centred on the orbit by custom properties that mirror the hero grid, fading out toward the hero's top and bottom), `.volumes`/`.volume`, `.fig`. The entity is
`<div class="nts-penrose" role="img" aria-label="…"><!-- nts:still philo --><!-- /nts:still --></div>`;
philo.js appends a canvas and hides the still. Colours from
`--penrose-ink`, `--penrose-cut` (the title's red, `--philo-red-key`, on
arrival from the home too), `--penrose-ground`. The host class and these
tokens keep the names they had for the bar triangle: they are internal, and
renaming them would touch every page copy and palette test.

The figure (`cubes.js`) is Reutersvärd's impossible triangle of nine
cubes, going round. The model is a staircase of unit steps along x, y and
z, climbing toward the viewer and seen isometrically (drawn mirrored, the
1934 drawing's way round), so that seen straight on place 9 stands exactly
in front of place 0: that is what closes the loop.

- **The loop's order.** Straight on, where two cubes overlap the one
  further along the loop is in front (each cube covers the next, and at
  each corner the cube after it covers the one before). No back-to-front
  order paints a cycle, so the compositor breaks it at the cube nearest the
  tip, clips any cube painted after one that should cover it at that cube's
  edge, and draws the covering cube's outline again on top (not over cubes
  already painted that cover it). Because all nine move together, no pair's
  order changes during a tick, so nothing pops.
- **The motion.** Every 1.5 s all nine step one place together (the last
  0.42 s of a tick); straight on, the cube crossing from place 8 to the tip
  goes straight to place 0. Cubes 0, 3 and 6 each carry one red face for
  good (top, dark, left), so the red rides round and every ninth tick is
  the starting picture again.
- **The screw, turned.** The nine are the top turn of an endless staircase
  (`TURNS` turns drawn below, fading into the ground): every cube climbs a
  place per tick, the one stepping off the top fades out by opacity, and
  the one arriving at the tip comes up from the turn below. Places are
  counted again from the top at each tick, so the screw itself stays put.
  The figure draws back as it turns (scale 1 / (1 + sin θ)), so more of the
  screw fits.
- **The handover.** Between 1° and 6° off the straight view the turned
  layer (the screw in true depth, by a plane between each overlapping pair)
  is drawn over the straight one (the top turn in the loop's order) with
  growing opacity, on a second canvas; past 6° only the screw is drawn.
  Straight on only the nine are drawn, so the closed picture is the same at
  every rest pose.

philo.js repaints only when the drawing would change: a frame repaints when
the motion's phase or the turn has changed, or while a bleed-in twin is open;
anything else that invalidates the canvas (a resize, new colours, a restart
after the loop stopped) goes through `draw`/`redraw` or clears the record of
the last frame.

`paint()` returns the drawn cubes' outlines, which philo.js hit-tests a
press against; `frame()` and `composite()` are what `tools/gen-stills.mjs`
records into the scripts-off still. `tests/static/cubes.spec.mjs` checks
the model and `tests/behaviour/philo-figure.spec.mjs` the drawing.

INTERSECT (`worlds/intersect.css`, `worlds/ascii.js`). The world sets IM
Fell as the body and heading face and the mono for labels; the title is
IM Fell behind a mono `>` prompt (the hero lines: World hero text). Classes: `.corr` (the correspondence
table), `.intersect-grain` (a grain div, first in body).
The entity is `<pre data-nts-ascii="tetra" data-cols="52" role="img" aria-label="…"><!-- nts:still intersect-lg --><!-- /nts:still --></pre>`;
figures: `tetra`, `heptagram`, `seed`. Live, `ascii.js` moves the baked
still into a hidden `span.ascii-still` and draws the glyphs on a canvas
over the pre's box, one `fillText` per line, in the pre's computed face
and colour, without a glow (on the page and in the fragments alike);
writing the text into the pre made the page lay out on
every frame. Those values are read at mount, on a resize and at the
bleed-in's start and end, never per frame, so a style that changes the
pre's colour at any other moment needs a redraw. The pre stays the box,
the accessible element and the target of drag and keys; the baseline
comes from a probe line in the same face at line-height 1, so the glyphs
sit where the pre's own lines put them (within a device pixel).
The size comes from `fit()`: the solid's mean silhouette span over every
pose a turn or a drag reaches (`SPAN.hero`, 0.97 of the ring, geometric;
the glyphs add about 5%) or its fragment's (`SPAN.fragment`), capped so
its furthest reach, a bound over all rotations, keeps a glyph clear of the
canvas. The page's canvas reaches 16.2% past the pre across and 17.6% down
(`intersect.css`), so the widest poses overshoot the ring as the other
worlds' figures do; `main` clips sideways overflow on that page. The
canvas sets a small face on whole-pixel advances, so the text is scaled
across to the cell width; the cell and each line's origin are snapped to
device pixels, so a glyph has the same ink wherever it falls. `tools/gen-stills.mjs` bakes each still as the
first live frame (`POSE` at the live zoom), and the pre's font size makes
the still's grid span the box as the live glyphs do. The overshooting tip
of a wide pose can't be grabbed: the canvas is `pointer-events: none` and
a press counts only on the pre. The solid is drawn by its edges: its faces
write depth but no glyph (0.05 further back, so a front edge wins against
its own faces), which hides the edges behind. 52 columns on the page and in a fragment (the same frame,
smaller).

A press grabs a figure only on the figure, in all three worlds
(`NTS.grab` in `nts.js`): the world gives a test of a point against the
outline it last drew (EMBERS: the hull of the solid's four turned vertices;
philo: its drawn pieces, tested in model units; INTERSECT: the hull of the
last frame's glyphs, from the ends of each row), with `NTS.grab.SLACK`
(14px) around it. `watch` returns `down`/`up` for the drag handlers and puts
`.is-grab` (hover over the figure, mouse and pen) and `.is-grabbing` on the
host, which the stylesheets turn into the cursors. A press elsewhere starts
nothing and captures nothing, so scrolling and clicks go through. The test
runs on pointer events only; the keyboard is unchanged.

## Fragments (for the home page)

One element per world, anywhere, any size (they are square):

```html
<div data-nts-fragment="embers"></div>      <!-- the hearth, small, 24fps, no embers, not interactive -->
<div data-nts-fragment="philo"></div>       <!-- the impossible triangle, 15fps -->
<div data-nts-fragment="intersect"></div>   <!-- the ASCII tetrahedron, 15fps; data-cols, data-figure -->
```

Sync fills each with a still (`.still`) so the page reads with scripts
off; the world's script adds the live layer and sets `.is-live`. They
inherit `border-radius` and take `--frag-bg` for the ground. They pause
off-screen and in hidden tabs. Load the three world stylesheets and
scripts on the home page (as `index.html` does); the fragments need
them. For tuning, the same data attributes as the entities apply
(`data-spacing`, `data-size`, `data-spin`, …).

Inside an aperture (the home's world windows) one figure animates at a
time. `nts.js` keeps the coordinator, `NTS.live.join(host, set)`: a figure
calls it at mount (it returns whether the figure may animate; `true`
outside an aperture) and `set(on)` tells it later. Live is the figure
whose window is open (`.is-open`, so a figure holds still while its disc
opens; every window counts as open where the latch does not run) and
whose host is nearest the middle of the viewport: the most of it inside
the middle 40% band, else the one most in view if at least half of it
is. Two IntersectionObservers per host feed it (the band, and the whole
viewport), and the latch calls it again when a window opens; nothing is
measured during the scroll. A held figure keeps its last frame and its
clock stops (each figure counts its own time from frames it drew), so it
resumes from what it shows, with no jump.

## The content source and sync

`_nts/content/copy.json` holds every line of copy, by key. In the HTML an
element carries `data-nts-copy="key"` and sync rewrites its inner HTML; a
`<meta … data-nts-copy="key" content="…">` gets its `content` rewritten
(tags stripped). `site.json` holds the initiatives (below), the footer,
the handles.
`events.json` is the ledger (fields: id, date, display_date, title, kind,
world, place, line, status, link). To change copy or add an event, edit
the JSON, run `node tools/sync.mjs`, commit both. The text is also in the
HTML, so pages stay readable and greppable; the JSON wins on conflict.

A copy value may hold markup (tags are stripped only for `<meta>`). The EMBERS
wordmark does: `embers.title` and `home.embers.label` wrap each E in
`<span class="xi">`, because Archivo has no Greek and a real Ξ would fall back to
another font. The E stays text for search, readers and copy; `.xi` paints it
transparent and draws the Ξ bars in its box (`worlds/embers.css`). The link preview
needs plain characters, so `embers.og.title` holds a real Ξ (U+039E).

Regions sync fills: `nts:sprite`, `nts:header`, `nts:footer`,
`nts:emblem core|orbits`, `nts:events` (with options), `nts:still <name>`, plus
the `data-nts-copy` and `data-nts-fragment` attributes, and `data-bleed` on
the `nts-head.js` script tag. It only touches what is between markers, and
it is idempotent: `--check` is safe in CI (S1 in `tests/static/sync.spec.mjs`
runs it).

Regions in the shared CSS and JS. In `_nts/**` sync fills the initiatives'
wiring between `/* nts:<name> */` and `/* /nts:<name> */`, each alone on its
line. Each region sits once, in its own file; an unknown, misplaced,
unclosed or missing one, or a registry entry missing a field, stops sync
with exit 1 (S3). This table, the list in `tools/sync.mjs`'s head and the
files are kept in step by S2 in `tests/static/sync.spec.mjs`:

| region | file | what it holds |
|---|---|---|
| `worlds` | `nts-head.js` | `BODY` (page to the home's body) and `PATHS` (`NTS.world`) |
| `orbits` | `orrery.css` | each body's start angle, period, direction |
| `riders` | `orrery.css` | each body on its orbit (`--r` from `r` of the emblem's 202) |

| `dots` | `apertures.css` | a world's code dot on the black ledger |

## Adding an initiative

The registry is `initiatives` in `site.json`, in nav order: each entry is a
page the orb morph runs between (the three worlds, and `/events/`, an NTS
page with `world: "nts"`). Its fields: `slug` (the folder and URL), `world`
(the key: `data-world`, `data-of`, the kit's name, `--code-<world>`),
`name` (nav and footer), `body` (the home bead's `data-body`), `bleed`,
`orbit` (`r` in the emblem's 202, start angle `a`, period `p`,
direction `d`) and `colours` (`sigil`; `face` base, sigil, text; ledger
`kind` bg, fg: a token as `--name`, else a literal colour); `colours` is
required of every entry but an NTS page. Besides sync, these read the
registry, so they need no edit: `tools/publish.sh` (the pages it checks
live), `tools/bench.mjs` (its default paths) and the tests' lists of pages,
worlds, bodies and code tokens (`tests/helpers/registry.mjs`).

1. The colours: the world's fixed tokens (`--<world>-*`) and its
   `--code-<world>` in section 1 of `nts.css`. They stay there, not in the
   kit, because pages that do not load the kit read them (the nav's sigils,
   the ledger, the beads on `/events/`). Its sigil in `tools/gen-sigils.mjs`.
2. The kit: `_nts/worlds/<world>.css` (its `--w-*` set on
   `[data-world="<world>"]` and what it undoes before the bleed), its
   scripts, and its stills (`gen-stills.mjs`, `STILLS` in sync).
3. The registry entry, then the page `site/<slug>/index.html` from the
   skeleton, with `<body data-world="<world>">` and its kit loaded.
4. The home and `/events/`, by hand, since they are design: the bead on
   the orrery (`.pivot.orbit.o-<body>`), the window (`section.world` with
   its `.orb`), an orbit the emblem draws (`ORBITS` and `STARS` in
   `gen-emblem.mjs`), the stop pose (`STOP_BODY` beside `STOP_DOTS` in
   `orrery.js` and `emblem.spec.mjs`), the bead pulse stagger
   in `orrery.css` (the 18 s cycle is cut for four bodies), the window's
   heading voice (`.world[data-world="<world>"] h2` in `orrery.css`), and
   the bead on the events page's small orrery (its `.mini-ring`, `.pivot.oN`
   and the `.events-hero .oN, .ring-N` radius and orbit in `orrery.css`).
5. `node tools/sync.mjs`, then `npm test`: R0 to R4 in
   `tests/static/registry.spec.mjs` name whatever is still missing.

Generated files, and how to regenerate them: `sigils.svg` from
`tools/gen-sigils.mjs`; `parts/emblem-*` from `tools/gen-emblem.mjs`; `parts/still-*` from `tools/gen-stills.mjs` (it
requires `cubes.js` and `ascii.js` through node, which is why both
export `module.exports`; it records cubes.js's canvas drawing as SVG). PHILO's
stills are the live canvas's first frame: `cubes.REACH` and `cubes.REST`
(page and fragment) size both `philo.js` and the bake, `still-philo.svg` for
the page and `still-philo-sm.svg` for the home's fragment (sync picks
`<world>-sm` for a fragment when it exists), and the fragment's `.still`
fills the host as the canvas does (`tests/layout/philo-still.spec.mjs`).
`node tools/gen-stills.mjs --check` exits 1 if a committed still is stale,
which `tests/static/stills.spec.mjs` runs.

## Redirects

Every URL an earlier draft of the site served (the design rounds' folders
such as `/eclipse/…`, `/doors/…`, `/threshold/…`, `/_base/…`, and the
`/archive/…` of earlier rounds) has a stub at its old path: a page with a
`<meta http-equiv="refresh">` to its equivalent, a canonical link and a
plain link. A design folder's page goes to the same page here
(`/frame/intersect/` to `/intersect/`, `/doors/` to `/`); anything under
`/archive/` goes to `/`. They carry no sync markers, so sync skips them.
To retire a page, leave the same kind of stub at its path.

## Publishing

`site/` is published as the `site` branch, which GitHub Pages serves:
`git subtree split --prefix=site` from the branch being published gives a
commit that fast-forwards `site`. `tools/publish.sh` does the split, the
fast-forward push and the live check; it runs no test suite of its own, so the
suite (`npm run test:publish`) is run on the commit beforehand. The live check
(`--live-only`, also run after the push) passes once GitHub's latest Pages
build is `built` for the commit `origin/site` points at and every page answers
200.

`tools/publish.sh` is the only way `site` moves, fast-forward only, never with
`--force`. The branch it splits is `main`; `NTS_BRANCH` overrides it.
`--dry-run` prints the split SHA without pushing, and `git diff origin/site
<split sha>` (after `git fetch origin site`) is what a publish would change.
An unchanged `site/` exits 0 with "nothing to publish". The split goes through
a temporary local branch `site-publish`, deleted at the start and end of each
run, so that name is not used for anything else.

The script refuses a dirty working branch, the working branch (`main` or
`NTS_BRANCH`) not checked out in any worktree, that branch moving during the
checks, `site` checked out in a worktree, a diverged `site` and a failed sync
check. `site` is never edited directly; fix the cause on the working branch.

The post-push poll retries 10 times, 30 s apart, because the Pages build can
lag; `--live-only` is one pass, so rerun it before a timeout counts as failed.
The domain may not resolve on a dev host: the script pins the address; any
other live curl needs `--resolve nexttuesday.art:443:185.199.108.153`.

## Checks before a change lands

`npm ci` once per checkout. Tiers are tags in test titles
(`playwright.config.mjs`); each spec file belongs to one project, and each
runs against a headless Chromium (`$CHROMIUM`) and an offline copy of the
fonts.

- `npm test`: the static and fast tiers, everything but `@slow`, `@perf` and
  `@visual`. About 2 minutes.
- `npm run test:publish`: all of it, adding the `@slow` sweeps, the `@visual`
  snapshots and the `@perf` guards (frame pacing and paint counts against `tests/perf/perf-baselines.json`).
  About 7 minutes.
- `npm run test:perf`: the `@perf` guards alone, without their setup project.
- `npm run test:visual`: the `@visual` screenshot comparisons alone;
  `npm run test:update-visual` rewrites their snapshots.

The npm scripts go through `tools/run-suite.mjs`. Playwright uses 4 workers
(`--workers` overrides). The timing tests fail on a loaded machine: run one
suite at a time.

They replaced these hand checks: phone widths 320, 360 and 390 with no
horizontal overflow, and a clean console with no 404s (the page walk in
`tests/static`); the bleed-in sequence on arrival, scroll and back
(`tests/transitions`); the orb morph between pages (`tests/transitions`);
hero, figure and card geometry (`tests/layout`). Still by hand: the
contrast audit over every text node (all AA, nothing under 11px, settled
on every page), and looking at screenshots from the preview
(the site served from the checkout).

Tests that open a fresh browser context use `coldPage`
(`tests/helpers/cold.mjs`); the font cache and the external-request block
come from one installer in `tests/helpers/fixtures.mjs`.
